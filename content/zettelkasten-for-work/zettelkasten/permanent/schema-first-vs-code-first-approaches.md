# Schema-first vs. Code-first approaches

Reasons to use [[code-first-approach]]:

- Rapid development. Useful if we're not caring about stakeholders and just need to create something fast.

Reasons to use [[schema-first-approach]]:

- Code is documented as it is written.
- Definitions and structure of the API can be planned.
- Does not block front-end development or testers due to unimplemented features in the back-end.
- Code generators can be used to save time writing classes and boilerplate code.
    - [[openapi-generator]].
